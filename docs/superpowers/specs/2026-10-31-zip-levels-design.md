# Zip Levels — design

Date: 2026-10-31
Status: approved, not built
Branch: `feat/zip-levels` (from `master` at `34954de`)
Admin half: winklo-admin (Levels tab, `level_worlds` routes, Generate world), specified in [Admin](#admin-winklo-admin) below

## Problem

Winklo has one puzzle per game per day, plus the archive and practice. A player who clears today's Zip in a minute has nothing to work through: practice boards are endless and look the same, so they don't go anywhere. Popular puzzle apps keep players with a run of levels that start easy and climb, shown as a map.

## Goal

A **Levels** mode for each game, starting with Zip: 100 fixed levels from 4×4 to 8×8 in five themed worlds, played in order on a winding map, with up to three stars per level, progress that follows the account, and content that is made and tuned in winklo-admin without an app update.

## Decisions

| Topic | Choice |
|-------|--------|
| Map style | One winding path through **themed worlds** (Ink, Metro, Embroidery, Neon, Sparkler: the worlds of the Play Store reels). Each world has its own backdrop and board size; worlds are joined where one material meets the next |
| Where levels come from | **Firestore, one doc per world** (`level_worlds/zip_1` … `zip_5`), edited in winklo-admin. 5 reads on first open, cached afterwards; a loaded world plays offline |
| Content at launch | **5 worlds × 20 levels**, generated by an admin "Generate world" button with a difficulty ramp and a suggested target time, then tuned by hand |
| Stars | **Mixed**: 1 for clearing, +1 for no hints, +1 for a time at or under the level's `targetSeconds`. Counted per run; the level keeps its best run's stars |
| Hints | No time is added in Levels (they already cost a star). The button says "Hint · costs a star" until the first hint |
| Clock | **No live clock** (the "no timer you didn't ask for" promise). The target is shown; the time is seen on Results |
| Unlocking | **One by one.** Clearing a level opens the next; clearing a world's last level opens the next world. Stars never gate anything |
| Progress | Local first, **synced** to `users/{uid}/level_progress/zip`. Merge = highest stars and lowest best time per level, so it can't conflict |
| Entry point | **Its own nav tab**, second: Home, Levels, Board, Profile. A game switcher at the top (Zip; Path Words and Sudoku "soon") |
| Level identity | Stable ids (`zip_1_07`); level numbers ("Level 27") are worked out from world order. A published world's level list is locked |
| Motion | **Few animations, all made of the line and each world's material.** No idle motion and no stock effects (see [Motion](#motion)) |
| Icons | No emoji anywhere: the player's critter SVG, drawn stars and padlocks, `AppIcons` (Phosphor duotone) |

## Data

### `level_worlds/{game}_{order}`

```jsonc
{
  "game": "zip",
  "order": 1,                // world number on the map
  "published": true,         // players only ever see published worlds
  "theme": "ink",            // ink | metro | embroidery | neon | sparkler; anything else draws a plain navy backdrop
  "title": "Ink",            // CMS label only; the app shows AppStrings.levelWorldName(theme), so Malayalam works
  "levels": [                // 20 by default, in play order
    {
      "id": "zip_1_01",      // stable; progress is keyed by it
      "size": 4,
      "numbers": { },        // ZipLevel.toJson shape: numbers, walls, solution
      "walls": [ ],
      "solution": [ ],
      "targetSeconds": 20    // time for the third star; missing or ≤ 0 hides that goal
    }
  ],
  "updatedAt": "<server timestamp>"
}
```

- Boards use the existing `ZipLevel` JSON, so `ZipLevel.fromJson`, `ZipBoardEditor` and the admin `zip.ts` validator work unchanged. 20 boards of up to 8×8 is roughly 20–40 KB, far under Firestore's 1 MB document limit.
- **Level numbers are worked out**: level *n* of world *w* is the sum of the earlier published worlds' lengths plus *n*. Because a published world's list is locked (see Admin), numbers never move.

### `users/{uid}/level_progress/{game}`

```jsonc
{ "levels": { "zip_1_01": { "stars": 3, "bestSeconds": 14 } }, "updatedAt": "<server timestamp>" }
```

- A local copy (SharedPreferences JSON) is the source the UI reads synchronously; the doc mirrors it.
- **Stars are per run**: a run's stars are `starsFor(usedHints, seconds, targetSeconds)`; the level keeps `max(stars)` and, separately, `min(bestSeconds)`. A 3★ level needs one clean, fast run.
- **Merge** (local ⊕ remote) takes per level the higher stars and the lower best time. It is commutative and only improves, so sync order never matters. Entries with stars outside 1–3 or a best time below 1 are dropped and reported through the existing client-error report.

### Derived map state

`level_map.dart` turns worlds + progress into the map: each node's global number, state (done / current / locked) and stars; each world's star total and whether it is open. **Current** = the first level, in map order, that isn't cleared. A world is open when every level of the world before it is cleared. Nothing about unlocking is stored.

## App architecture

Levels is a fourth play mode next to daily, archive and practice, so it rides the existing off-daily paths.

### `domain/` (pure Dart)

- `play_mode.dart`: `PlayModeKind.level`, `PlayMode.level(levelId)`. Route `/zip?mode=level&level=zip_1_07`; `runId` = `level_zip_1_07` (drafts); `isDaily` false, so streaks, leaderboards, the daily best, `daily_activity`, the widget and the reminders never see level runs. `fromQuery` returns null for a malformed level id; the router sends that to `/levels`.
- `entities/level_world.dart`: `LevelWorld` (game, order, theme, levels), `LevelEntry` (id, targetSeconds, board → `ZipLevel`).
- `entities/level_progress.dart`: `LevelRecord {stars, bestSeconds}`, `LevelProgress` (id → record, `merge`, `record(id, stars, seconds)`).
- `logic/level_stars.dart`: `int starsFor({required bool usedHints, required int seconds, required int? targetSeconds})`. **Written by the user** (learning-mode contribution), test-first. Rules to settle in it: equal to the target counts as beating it; a missing or non-positive target can't earn the time star; a cleared run is never below 1★.
- `logic/level_map.dart`: the derived state above.
- `repositories/level_world_repository.dart`: `Future<List<LevelWorld>> publishedWorlds(String game)`, `Future<LevelEntry> level(String levelId)`.
- `repositories/level_progress_repository.dart`: synchronous `progress(game)`, `Future<LevelClearResult> record(levelId, stars, seconds)` (previous and new record, improved flags), `Stream<void> changes`.
- `usecases/record_level_clear.dart`, `usecases/sync_level_progress.dart` (pull, merge, save locally, push if changed). `SyncProgress` calls it in its existing pass; ownership follows the signed-in uid like the dailies (an account switch swaps maps, never merges them).
- `hint_penalty.dart`: `appliesTo` is false for level mode as for practice.

### `data/`

- `level_world_repository_impl.dart`: query `level_worlds where game == zip, published == true orderBy order`, server first and cache on failure (the pattern of `firestore_read.dart`). `level(id)` reads from the loaded worlds, loading them if needed.
- `level_progress_repository_impl.dart`: SharedPreferences store keyed by uid and game; remote doc read/write.
- Remove the dead paths in `zip_level_repository_impl.dart`: `fetchLevels()` (an unreachable `zip_levels` list query that the rules would refuse) and `assets/zip/levels/*`.

### `features/levels/`

- `cubit/level_map_cubit.dart`: loads worlds and progress, rebuilds on `changes`; states loading, ready, empty, unavailable. Knows the pending animation (the newest progress the map hasn't shown yet), so each new clear is drawn exactly once.
- `view/levels_screen.dart`: header (title, total stars as a drawn star + "11 / 300", game switcher) and the map, scrolled so the current level sits a little below the middle.
- `view/widgets/level_path_painter.dart`: the winding path, nodes, and the line drawn so far.
- `view/widgets/world_backdrop.dart`: one painter per theme, plus the *unprinted* version used while a world is locked.
- `view/widgets/level_sheet.dart`: a standard `showModalBottomSheet`: world, "Level 4", board size and best time, the three goals with the best run's marks, and Play / Replay. Locked levels show a short "Clear Level 5 first" message and no sheet.

### Changes to existing code

- `ZipBloc._startOffDaily` / `_completeOffDaily`: level mode loads the board from `LevelWorldRepository`, adds no hint time, and on a clear calls `RecordLevelClear` and builds Results arguments for a level.
- `play_mode_strip.dart`: level mode shows "Level 7 · Ink" and the three goal marks; the no-hints mark goes hollow the moment a hint is used.
- `results_args.dart` / `local_results_view.dart`: `LocalResultKind.level` (below).
- `app_router.dart`: `/levels` as a new `StatefulShellBranch`, second; `floating_nav_dock.dart` gets four tabs; `AppIcons.levels` (Phosphor map-trifold).
- `AppStrings` (English and Malayalam): tab, world names, goals, sheet, Results and error copy.
- Analytics: `game_started` / `game_completed` with `dayId` = level id as today, plus `level_cleared {level, world, stars, improved}`.

## Map screen

- **At rest nothing moves.** Cleared levels are drawn in their world's medium (Ink: a brushed ensō with the number); the current level carries the player's critter avatar on a pin; locked levels are faint (Ink: pencil circles); the road ahead is a dotted pencil line.
- **Stars in the world's medium**: Ink = vermilion seals, Metro = dots in the line's colour, Embroidery = French knots, Neon = lit letters, Sparkler = embers. Filled = earned, outline = not. The header total uses a drawn star.
- **Locked worlds are unprinted**: only their outlines show, with "World 2 · Metro · 5×5" and a drawn padlock.
- A world label on each world with its star total.
- Empty, offline and "all cleared" states: see [Errors](#errors).

## Motion

Three event animations, nothing idle, no stock effects (no pulse rings, bobbing, sparkles, bursts, shimmer, glow borders, spring overshoot, shakes or cascades).

| Moment | Motion | Timing | Reduced motion |
|---|---|---|---|
| Map opens | None; scroll to the current level | — | — |
| After a new clear (on return to the map) | The line is drawn on to the next node in the world's medium, and the critter rides its tip. Ink: a brush stroke (slow-fast-slow), glossy then drying matte, the next pencil circle brushed over, seals pressed one by one. Metro: a route inked at constant speed with 45° bends; the next station turns from hollow to white; dots appear. Embroidery: stitched in dashes. Neon: the tube lights segment by segment. Sparkler: a light trail that settles into a long-exposure line. One haptic tick when the line reaches the node | 1.2–1.8 s; a tap skips to the end | Final state |
| Entering a new world | The line runs to the edge of one material and carries on in the next (brush stroke → metro route). The locked world switches from unprinted to printed **in one cut** the moment the line touches it; the line reaches the first level, which opens | ≈2.8 s; a tap skips | Final state |
| Replaying a cleared level | No line animation; only new marks (if the stars went up) are pressed | ≤0.4 s | Final state |
| Level sheet | Platform default | — | — |

Reference mockups (not shipped): `.superpowers/brainstorm/*/content/map-screen-v3.html`.

## Playing a level and Results

- The Zip screen in level mode: the strip above, no New board, no live clock, hints free of time but costing the no-hints star.
- Drafts under `level_zip_1_07`; a board edited in the CMS changes its fingerprint and the draft is dropped (existing check).
- **Results** (`LocalResultKind.level`): "Level 7 cleared", the time with the target ("0:24 · target 0:30"), the three goals earned or missed in the world's medium, each missed one saying how to earn it ("Replay without hints"); "New best · 2 → 3 stars" or "New best time" when improved. No celebration effect.
- Actions: **Next level** (primary) returns to the map, plays the line animation, then opens the next level's sheet; **Replay**; **Map**. On a world's last level the primary is **Open World 2** (plays the crossing). On the last published level the primary is **Map**, and the map's top reads "More worlds coming soon".

## Rules and deletion

- `firestore.rules`:
  - `match /level_worlds/{id}`: `allow get: if resource.data.published == true || isAdmin()`; `allow list: if resource.data.published == true || isAdmin()` (players' queries must filter on `published == true`); `allow write: if false` (admins write through admin-api).
  - `match /users/{uid}/level_progress/{gameId}`: owner read; owner create/update when `validLevelProgress(gameId)` (game in zip / path_words / sudoku, `levels` is a map, `updatedAt == request.time`); no delete. Per-entry checks live in the app's merge; level progress never reaches a leaderboard, so editing it by hand only changes one's own map.
- `firestore.indexes.json`: `level_worlds (game ASC, published ASC, order ASC)`.
- `workers/account-deletion/src/firestore_wipe.ts`: add `level_progress` to the wiped subcollections.

## Admin (winklo-admin)

- `workers/admin-api/src/content_cms.ts`: `level_worlds` list / get / save / publish / unpublish behind `admin_auth`.
- Content → **Levels** tab (`collections.ts`, `types.ts`): worlds per game; a world opens as its levels in order, each edited with `ZipBoardEditor` and checked by `validators/zip.ts`, plus a target-time field and the theme dropdown (the five themes).
- **Generate world** (`generators/generateZip.ts`, sharing `zip_difficulty.ts`): size and level count in; a ramp out (early levels more numbers and fewer walls, later fewer numbers and more walls); every board validated; suggested `targetSeconds` = cells × a per-size factor, editable. Allowed on unpublished worlds only.
- **Publishing locks the level list**: boards and targets stay editable; adding, removing or reordering levels is disabled.
- **Worlds publish in order and stay published**: admin-api refuses to publish world *n* while world *n − 1* is unpublished, and refuses to unpublish a world while a later one is published. Together with the lock, this keeps every level number fixed.

## Errors

| Situation | Behaviour |
|---|---|
| First open, no connection, no cache | Card: "Levels need a connection the first time" + Retry. The tab never errors out |
| Server slow or refusing, cache present | Load from cache; cached worlds play offline |
| No published worlds | "Levels are coming soon" |
| Level id in a link or draft no longer exists | ZipBloc's failed state with a Map button; the draft is dropped |
| Board edited in the CMS mid-run | Fingerprint mismatch drops the draft; the level starts fresh |
| Clear while offline | Recorded locally, map updates; synced on the next pass |
| Unknown theme / missing or ≤ 0 target | Plain navy backdrop / the time goal is hidden and a clean run tops out at 2★ |
| Invalid remote progress entries | Dropped in the merge and reported |

## Build order

1. Admin and data: rules, index, admin-api routes, the Levels tab, Generate world; make World 1 (Ink) and keep it unpublished.
2. App domain and data: `PlayMode.level`, entities, `starsFor`, `level_map`, repositories, sync, the deletion wipe.
3. Level play: ZipBloc level mode, the strip, the hint label, Results.
4. The map: the tab and nav, static Ink and Metro worlds, the sheet.
5. Motion: Ink and Metro lines, the world crossing, reduced motion.
6. Embroidery, Neon and Sparkler: backdrops and line materials; generate and publish worlds 3–5.

Steps 1–5 can ship with Worlds 1–2 published; a later world needs an app update only when it brings a new material.

## Out of scope

Path Words and Sudoku levels (the tab, `level_worlds` and `level_progress` are already per game), level leaderboards, star-gated unlocks, rewards for stars, sound for the line.
