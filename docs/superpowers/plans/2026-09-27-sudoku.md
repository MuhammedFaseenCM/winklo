# Sudoku Daily Game Implementation Plan

> **For agentic workers:** Use subagent-driven-development or executing-plans. Steps use checkbox tracking.

**Goal:** Ship Sudoku as a third daily competitive game: one seeded 6×6 puzzle per day, Flame board, Bloc-owned play state, Zip-style score/streak/leaderboard/results.

**Architecture:** Pure domain generator + rules; `SudokuBloc` owns play/timer/win; Flame only renders and forwards cell taps; Flutter chrome for number pad/notes/hint/reset. Reuse existing score/streak/leaderboard usecases.

**Tech Stack:** Flutter, Flame, flutter_bloc, freezed, existing Winklo domain usecases.

**Global constraints:**
- All user-facing copy via `AppStrings`
- Domain must not import Flutter
- Flame must not own timer/hints/score
- TDD for domain + bloc
- `dart format` after edits

**Approved design:** See `docs/superpowers/specs/2026-09-27-sudoku-design.md`.

## Tasks

1. Design spec + `GameIds.sudoku` + `SudokuScoring`
2. Domain entities + rules with tests
3. Seeded 6×6 generator with difficulty rotation
4. SudokuBloc + finish/score pipeline
5. Flame board + SudokuScreen + `/sudoku` route
6. Home card/streaks, leaderboard allowlist, tile asset
7. Verification tests
