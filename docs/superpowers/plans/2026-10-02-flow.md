# Flow Daily Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Flow as a fourth daily competitive game: freehand connect matching colored endpoints with no crossings, seeded daily layout + Firestore override, Flame canvas, Bloc-owned play state, Zip-style score/streak/leaderboard/results.

**Architecture:** Pure domain geometry + rules + generator; `FlowBloc` owns paths/timer/win; Flame only paints dots/paths and forwards pointer samples; Flutter chrome for reset/how-to-play. Reuse `SubmitScore`, `RecordDailyClear`, `SubmitLeaderboardTime`. Hybrid puzzle load mirrors `GenerateDailySudoku`.

**Tech Stack:** Flutter, Flame, flutter_bloc, freezed, Firestore (override reads), existing Winklo domain usecases, `bloc_test` / `flutter_test` / `mocktail`

**Spec:** `docs/superpowers/specs/2026-10-02-flow-design.md`

## Global Constraints

- All user-facing copy via `AppStrings` (no inline UI strings)
- `domain/` must not import Flutter/UI (`package:flutter/*`, widgets, `BuildContext`)
- Flame must not own timer, win, scoring, or crossing policy
- TDD for domain geometry/rules/generator and FlowBloc
- Prefer `dart format`; run timed `dart analyze` / `flutter test` on touched files only
- No drive-by refactors outside Flow integration
- No grid / cell painting / snap-to-grid
- Admin CMS endpoint editor is a **follow-up plan** in winklo-admin; this plan ships mobile with client generator + Firestore read shape ready for overrides

### Task 3: Geometry + stroke rules (TDD)

**Files:**
- Create: `lib/domain/flow/flow_geometry.dart`
- Create: `lib/domain/flow/flow_rules.dart`
- Create: `test/domain/flow/flow_geometry_test.dart`
- Create: `test/domain/flow/flow_rules_test.dart`

**Interfaces:**
- Produces:
  - `FlowGeometry.segmentsIntersect(FlowPoint a1, FlowPoint a2, FlowPoint b1, FlowPoint b2) → bool`  
    (proper intersection; touching at shared endpoint of the *same* polyline is allowed when checking consecutive segments)
  - `FlowGeometry.polylineSelfIntersects(List<FlowPoint> pts) → bool`
  - `FlowGeometry.polylinesCross(List<FlowPoint> a, List<FlowPoint> b) → bool`
  - `class FlowStrokeResult` with updated paths / rejected flag
  - `FlowRules` methods:
    - `hitEndpoint(FlowPuzzle puzzle, FlowPoint p, {double radius = 0.045}) → FlowEndpointHit?`  
      (`pairId`, `which` = `a|b`, `colorIndex`)
    - `beginStroke({required puzzle, required completed, required at}) → FlowPlaySnapshot`
    - `extendStroke({required snapshot, required at}) → FlowPlaySnapshot` (reject if crosses)
    - `endStroke({required snapshot, required at}) → FlowPlaySnapshot` (must land on matching partner; else reject)
    - `clearPair({required snapshot, required pairId}) → FlowPlaySnapshot`
    - `reset(FlowPuzzle puzzle) → FlowPlaySnapshot`
    - `bool isWon(FlowPlaySnapshot snapshot)`
  - `FlowPlaySnapshot`: `completed: Map<String, List<FlowPoint>>`, `activePairId`, `activeFrom`, `activePoints`, `rejected`

**Crossing policy:** While extending, if the new segment would cross any completed path or the active path (non-adjacent), mark `rejected: true` and drop the active stroke (completed unchanged). Ending on wrong color / miss → reject active.

### Task 4: Seeded generator

**Files:**
- Create: `lib/domain/flow/flow_generator.dart`
- Create: `test/domain/flow/flow_generator_test.dart`

**Interfaces:**
- Produces:
  - `FlowGenerator.bandForDay(DateTime day, {Duration period}) → FlowDifficulty` (rotate easy→medium→hard by bucket day index)
  - `FlowGenerator.paramsFor(FlowDifficulty d) → ({int pairCount, double tangle})`  
    easy `(4, 0.25)`, medium `(6, 0.45)`, hard `(8, 0.65)`
  - `FlowGenerator.generate({required DateTime day, Duration period, int generatorVersion = 1, FlowDifficulty? difficulty, int? pairCount, double? tangle}) → FlowPuzzle`

**Algorithm (solvable by construction):**
1. Resolve band → `pairCount` / `tangle` (overrides win if provided).
2. Seed RNG from `dateId|generatorVersion|pairCount|tangle`.
3. For each pair `i`, place two endpoints near opposite sides of a reserved angular wedge / lane so default straight (or slight curve) connections do not cross; increase jitter with `tangle` but keep endpoints inside inset margin `0.08..0.92`.
4. Verify with a constructive witness: connect each pair with a simple polyline that stays in its lane (or straight line if non-crossing); if verification fails, re-roll that pair (bounded retries) then fall back to lower tangle.
